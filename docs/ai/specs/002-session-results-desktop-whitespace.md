## Context

После внедрения плана [`001-session-results-responsive-dynamics`](../plans/001-session-results-responsive-dynamics.md) на десктопе (в т.ч. ≥1440px) экран **Session Results** воспринимается с **избыточными пустыми зонами**: крупные вертикальные «полосы» внутри сетки, широкий зазор между колонками, доминирующая кнопка «Next Phrase» в нижней панели.

Техническая первопричина зафиксирована в review: при `lg:` CSS Grid с **`align-items: stretch` по умолчанию** ячейки в строке выравниваются по **высоте самого высокого** соседа; внутренние карточки не заполняют высоту ячейки — под коротким блоком остаётся пустое место до низа строки. Дополнительно усиливают эффект **`lg:gap-12`** и пропорции **`flex-[2]`** у Next.

## Goals

- **Вертикаль:** убрать ощущение «пустого коридора» между карточками в одной строке сетки на desktop (`lg:`), не ломая порядок секций и двухколоночную логику из `001`.
- **Горизонталь:** смягчить избыточный разрыв между колонками на desktop (без возврата горизонтального скролла страницы).
- **Нижняя панель:** сделать пропорции кнопок **Retry / Custom / Next** читаемыми на ширине контентной зоны (`max-w-6xl`, с **`xl:`** — `max-w-7xl`); Next не должен визуально «съедать» половину ряда за счёт одного только `flex-[2]`.
- **Регрессии:** сохранить требования `001`: порядок блоков mobile (`max-md`), двухколоночный `lg:`, панель `fixed` только на mobile, модалки + `isActionBarBlocked`, Word Analysis / Pitch / MetricBar как сейчас.

## Non-goals

- Смена контракта данных, Gemini, `App.tsx` маршрутизации.
- Замена Recharts или перенос Pitch в другой компонент.
- Обязательное расширение контентной ширины на всех брейкпоинтах — нет; **`xl:max-w-7xl`** (план 002 Step 4) применяется **с `xl:` вверх**, ниже по-прежнему `max-w-6xl`.

## User scenarios

1. Как пользователь **широкого монитора**, я вижу карточки **плотнее** сгруппированными: нет больших пустых полос **под** короткой карточкой в той же строке, что и высокая соседняя.
2. Как пользователь, я **понимаю** вес кнопок в нижней панели: Next заметна как primary, но Retry и Custom остаются удобными для тапа/клика.

## UI / UX

| Область | Ожидаемое поведение |
|---------|---------------------|
| Grid `lg:` | Нет растягивания «короткой» ячейки по высоте соседа **без** заполнения контентом/карточкой (предпочтительно: выравнивание по **верху** строки для grid-items на `lg:`, либо эквивалент с тем же визуальным эффектом). |
| `gap` на `lg:` | Умеренный зазор между колонками и строками (строгость — в плане: конкретные классы Tailwind). |
| Нижняя панель `md+` | Пропорции кнопок: не использовать «половину ширины» для Next за счёт одного только `flex-[2]` на полной ширине панели; варианты — в плане (например `flex-1` для всех + `max-w-*` на Next, или иные flex/min-width правила). |
| Ширина контентной колонки | До **`xl`**: `max-w-6xl`; с **`xl:`**: `max-w-7xl` на корне экрана и на ряду нижней панели (согласованно). |

## Acceptance criteria

- [ ] На ширине **≥1024px** (`lg:`) нет **аномально больших** вертикальных пустых полос **внутри** строки сетки из-за выравнивания по высоте соседа (визуальная проверка с длинным AI Feedback и коротким Score / Audio).
- [ ] Порядок блоков и колонок **как в `001`**: mobile — линейный DOM-порядок; desktop — левая колонка Score → Audio → Pitch, правая Feedback → Deep (если есть) → Words.
- [ ] Нижняя панель: **Retry / Custom / Next** выглядят сбалансированно на ширине контентной зоны; Next остаётся primary (цвет/жирность без регрессии).
- [ ] **Нет** горизонтального скролла основного контента на типичных desktop/tablet размерах (как в `001`).
- [ ] Mobile: sticky-панель, safe-area padding, модалки — без регрессии.

## Risks

- Смена `align-items` на grid может затронуть редкие случаи, если где-то ожидалось «вытягивание» по высоте (проверить Deep Analysis + Word Analysis в одной строке).
- Слишком узкий Next ухудшит CTA — баланс через `min-w` / иконки в плане.

## Open questions (Product)

- **Шире `max-w-6xl`:** реализовано в плане **002 Step 4** — с **`xl:`** (≥1280px) контент и ряд нижней панели расширяются до **`max-w-7xl`**; ниже `xl` остаётся **`max-w-6xl`**.

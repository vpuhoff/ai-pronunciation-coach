## Summary

На широких экранах (десктоп) между блоками Session Results остаётся **заметное «пустое» пространство**: карточки визуально «разъезжаются» по краям, центр и промежутки между рядами почти не заполняются контентом. Восприятие — **слабая адаптация под размер окна**: макет не использует доступную ширину/высоту осмысленно (фиксированные `max-width`, крупный `gap`, сетка `lg:grid-rows-3` без растягивания рядов и т.п.).

## Симптомы (как у пользователя)

1. **Горизонталь:** большой зазор между левой колонкой (Score, затем Reference / My Recording, Pitch) и правой (AI Feedback, Deep Analysis, Word Analysis) — блоки узкие относительно ширины окна.
2. **Вертикаль:** после первого «яруса» карточек — ощутимая пустота до нижнего ряда (кнопки воспроизведения / Deep Analysis / нижняя панель), будто контент «прижат» к верху и низу без заполнения середины.
3. **Нижняя панель:** кнопка «Next Phrase» с `flex-[2]` визуально занимает непропорционально много ширины на широком экране рядом с Retry / Custom.

## Ожидаемое поведение

- На разных размерах окна **плотность и баланс** макета остаются приемлемыми: нет огромных «мёртвых» полей без явного намерения дизайна.
- Либо контентная зона **ограничена и центрирована** с предсказуемыми полями, либо колонки/карточки **мягко растут** (`max-width`, `minmax`, fluid gaps) без разрыва визуального ритма.

## Шаги воспроизведения

1. Открыть приложение, пройти до экрана **Session Results** после анализа (желательно с блоком **Deep Analysis**, чтобы была правая колонка полностью).
2. Развернуть окно браузера на **широкий** монитор (например ≥1440px по ширине контента) или увеличить масштаб окна по ширине.
3. Прокрутить экран целиком и оценить зазоры между **верхним рядом** (Score / AI Feedback), **средними** секциями и **нижней** зоной (аудио / Deep Analysis / Pitch / панель действий).

## Технические гипотезы (для Architect / Coder)

- Корневой контейнер **`max-w-6xl`** + **`lg:gap-12`** на двухколоночной сетке усиливает ощущение «дырок» при большой ширине вьюпорта.
- **`lg:grid-rows-3`**** без** явного распределения оставшейся высоты — строки не заполняют доступную высоту, контент «прилипает» к началу строк.
- Нижний ряд: **Reference / My Recording** только в левой колонке, **Word Analysis** / **Pitch** — разнесение по колонкам при большом `gap` визуально раздувает пустоту между ними.
- Кнопки панели: **`flex-[2]`** на Next на очень широкой панели (`max-w-6xl`) даёт доминирующую ширину.

## Критерии закрытия бага (черновик)

- [x] На типичном десктопе (например 1440–1920px) нет **аномально больших** пустых полей между основными карточками (согласовать порог с Product: скрин / % от вьюпорта).
- [x] Поведение согласовано для **высоты** окна: нет ощущения «пустого коридора» между верхом и низом без осмысленного отступа.
- [x] Нижняя панель действий: пропорции кнопок читаемы на широкой ширине (или явное ограничение ширины группы кнопок).
- [x] Регрессия: порядок блоков по ТЗ (mobile / desktop), модалки, sticky-панель на mobile.

## Решение (кратко)

- План и спека **002**: шаги 1–4 + **замена синхронизированной по строкам CSS Grid на `lg+` двумя независимыми колонками `flex`** (`layoutLg` через `matchMedia`), чтобы высота левой и правой колонки не «тянулась» по самому высокому соседу в строке; при смене ширины — `resize` для Recharts.
- Файл: `components/ResultScreen.tsx`.

## Скриншоты

При необходимости приложить к задаче в трекере скриншоты из отчёта (верх экрана с Score / Feedback / Deep Analysis; нижняя часть с Pitch / Word Analysis / панелью).
